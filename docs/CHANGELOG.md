# Changelog

## Unreleased
- Documentación inicial: SSD canónica, STATUS, ADR-001 (stack) y matriz de trazabilidad.
- Monorepo npm workspaces: apps/api (NestJS 11, /health), apps/web (Next 16), CI (format, lint, tipos, build, tests, audit, gitleaks, CodeQL), docker-compose de desarrollo.
- Esquema inicial (Drizzle): cuentas, asignaciones de rol y auditoría; hash Argon2id de claves; pruebas de integración con PostgreSQL.
- Alta administrativa de cuentas (servicio): exige HR_ADMIN vigente, EST=V con contrato único, correo normalizado, clave temporal Argon2id y auditoría. Tabla employee_snapshots.
- Login y sesiones: POST /auth/login, GET /auth/me, POST /auth/logout; cookie HttpOnly SameSite=Strict, token de sesión hasheado, CSRF (HMAC) en métodos no seguros, bloqueo tras 5 intentos (15 min), expiración por inactividad (30 min) y absoluta (8 h), revocación por cuenta. Requiere SESSION_SECRET.
- Verificación por SMTP y activación: código aleatorio de un solo uso (8 caracteres, HMAC, 15 min, 5 intentos, máx. 3 envíos/hora) enviado al correo de EMPLEADOS; POST /auth/activate (clave temporal + código + clave nueva ≥12) y POST /auth/verify-email/resend; nodemailer con TLS exigido por defecto; Mailpit en docker-compose.
- Endpoint POST /admin/accounts (sesión + rol HR_ADMIN vigente + reautenticación en los últimos 10 min); POST /auth/reauth; guards Roles/RecentAuth; los administradores (HR_ADMIN/SYSTEM_ADMIN) pueden iniciar sesión sin contrato EST=V; comando `npm run admin:bootstrap` para crear el primer administrador.
- Importación de EMPLEADOS (.xlsx): POST /admin/imports/employees (staging, validación de encabezados, tipos, EST V/C, unicidad, un contrato vigente), GET /admin/imports/:id y /errors, POST /admin/imports/:id/apply (transacción con bloqueo, conteo verificado, conciliación por N_IDE+N_CONT, EST=C revoca sesiones). employee_snapshots con las 24 columnas de EMPLEADOS.
- Empresas y catálogos organizacionales: CRUD de empresas con control de versión (GET/POST/PUT /admin/companies); importación Excel de AREA, CCOSTO, CARGO y TIPO_CONTRATO (POST /admin/imports/catalogs/:kind, misma vista previa/aplicación atómica), historial de cambios de nombre, listado GET /admin/imports/catalogs/:kind; EMPLEADOS se valida contra empresa y catálogos publicados (código inexistente = error, descripción distinta = advertencia).
- Roles con alcance y jefes de área: POST/GET /admin/accounts/:id/roles (nadie se concede roles a sí mismo; HR_ADMIN/SYSTEM_ADMIN solo los concede SYSTEM_ADMIN; AREA_MANAGER exige empresa y área existentes); POST /admin/areas/managers, PUT /admin/areas/managers/:id/end y GET /admin/areas/:cEmp/:cArea/managers con vigencia sin solapes y bloqueo por área; resolveAreaManager(cEmp, cArea, fecha).
- Graphify: mapa del código local (`npm run graph`, `graphify affected/explain/path`), `.graphifyignore` que excluye Excel y datos, hooks locales, job informativo `graph` en el CI que publica el informe como artefacto, `CLAUDE.md` y `docs/graphify.md`.
- POST /auth/change-password: cada usuario cambia su clave con sesión, CSRF y clave actual (mínimo 12 caracteres, distinta de la actual); los intentos fallidos cuentan para el bloqueo; cierra las demás sesiones y conserva la actual; se audita sin guardar claves.
- Web: pantallas de ingreso, activación de cuenta (con reenvío de código), cambio de clave e inicio con perfil y roles; la web habla con la API solo a través del proxy `/api` (sin CORS); CSP en producción; GET /auth/me devuelve correo, nombre y roles vigentes.
- Stack local: `npm run stack:up|status|down` (scripts/stack.sh) con PostgreSQL, Redis, MinIO (puertos 9100/9101), Mailpit, API y web; `.env` local generado con SESSION_SECRET aleatorio; docs/local-stack.md.
- Pruebas e2e de la interfaz con Playwright/Chromium (16): ingreso, sesión, cambio de clave, activación con el código leído de Mailpit, cabeceras/CSP, accesibilidad (axe WCAG 2 A/AA), móvil, modo oscuro y teclado; job informativo `e2e` en el CI; `NEXT_DIST_DIR` para compilar la web de pruebas aparte.
- Volantes de pago (ESS-PAY-001): importación de NOMINA por alcance PER + N_LIQ (POST /admin/imports/payroll) con validación, conciliación de conteo y sumas exactas de DEV/DED, versiones (una sola publicada, correcciones = nueva versión, mismo contenido rechazado); GET /me/payroll y GET /me/payroll/:per/:nLiq/:contrato/pdf?mode=SIN_AJUSTE|ENTERO_SUPERIOR con PDF (pdfkit), acceso solo a los propios, auditoría de descargas sin importes; modo por defecto configurable por empresa; página web /volantes.
- Administración (ESS-ADM-001, API): catálogo de conceptos de nómina con unidades (CRUD + importación de CONCEPTOS.xlsx) y cantidad con unidad en el volante; logo de empresa versionado y reemplazable (PNG/JPEG hasta 512 KB, 64-2000 px), con logo genérico incluido; CRUD de áreas, centros de costo, cargos y tipos de contrato (baja lógica bloqueada si están en uso, historial de nombres); CRUD de empleados con motivo obligatorio, control de versión e historial de cambios; gestión de cuentas (listar, bloquear, desbloquear, restablecer clave); terminar roles; resumen, historial de importaciones y acceso a volantes ajenos con motivo. Todas las rutas /admin exigen perfil administrador (HR_ADMIN o SYSTEM_ADMIN), verificado por una prueba que recorre cada ruta.
- Auditoría: cada petición HTTP de todos los usuarios queda registrada (usuario, método, plantilla de ruta, estado, duración, IP, agente, id de petición) sin cuerpos, claves, códigos, tokens ni identificadores reales; GET /admin/audit consulta peticiones y actividades con filtros por tipo, usuario, método, estado, ruta y fechas.
- Administración (ESS-ADM-002, web): área administrativa en /admin solo para perfil administrador (acceso restringido para el resto; el servidor sigue siendo quien autoriza): resumen, empresas con carga y versiones de logo, catálogos (áreas, centros de costo, cargos, tipos de contrato) con CRUD e importación, conceptos de nómina con unidades, empleados (consulta, alta y corrección excepcional con motivo, baja y reactivación), cuentas y roles (crear cuenta con clave temporal única, bloquear, desbloquear, restablecer, conceder y terminar roles, asignar jefe de área), importaciones con vista previa y reporte de errores, nómina publicada con descarga de volantes ajenos con motivo, y visor de auditoría de peticiones y actividades. La reautenticación se pide en un diálogo y la acción se reintenta.
- Correcciones halladas por las pruebas de navegador: la edición de empresas ignoraba el modo del volante; la baja de un empleado exigía validar catálogos y ficha completa; ids duplicados entre diálogos y filtros; campo opcional vacío rechazado en importaciones; tablas desplazables sin acceso por teclado.
